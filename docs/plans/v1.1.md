# ventMail v1.1 — navigáció, profil, import, szerkesztő, journey canvas, Platform, analitika

## 0. Felmérés (2026-10-12, `main` @ 3e… a #41 után)

**Navigáció / layout.** `resources/js/Layouts/AppLayout.vue`: bal oldalsáv (Dashboard + Platform /
Studio / Settings / Console csoportok, `abilities` szerint szűrve), alul workspace-váltó (`VtSelect` →
`POST /workspace/switch`), nyelvválasztó (`POST /locale`), kijelentkezés (`POST /auth/logout`, ventSSO
RP-logout). Avatar / felhasználói menü nincs. Media query nincs (mobilon nem használható).
Spacing: kizárólag `--vt-*` tokenek (`--vt-space-1…32`), lokális primitívek `shell.css`-ben
(`vm-stack`, `vm-cluster`). Közös form-komponens NINCS — az oldalak `VtField`-et közvetlenül használnak
(~150 helyen), ezért a térközök oldalanként eltérnek.

**Sablonszerkesztő.** `templates.blocks` jsonb blokkfa; a séma a ventMail saját
`app/Modules/Template/Data/BlockSchema.php`-je (Draft 2020-12 JSON Schema-t emittál, „a ventStudióval
közös"); `MjmlWriter` → MJML → `MjmlCompiler` (saját, szűk PHP MJML→HTML fordító, Node nélkül) →
`PlainTextWriter`. Blokkok: section/column + heading, text, image, button, divider, spacer,
unsubscribe, social, html. A szerkesztő (`Pages/Template/Edit.vue`) listás, nincs drag-and-drop,
nincs verziótörténet (`templates`-en), nincs teszt-küldés. A `PublishToStoredTemplate` action-nek nincs
hívója. A sibling repókban (`../venture-*`, `../ventstudio`) NINCS blokkmotor — a ventStudio-blokkmotor
a gyakorlatban ez a `BlockSchema` + `MjmlWriter`.

**Journey.** `journeys` + `journey_steps` láncolt lista (`next_step_id`, `else_step_id`), lépések:
send_email, wait, condition, add_tag, remove_tag, exit; triggerek: form_signup, tag_added,
segment_entered, api_event, inbound_email. Futtató: `journeys:tick` percenként (`JourneyEngine`,
`lockForUpdate`, lépés-limitek). Verziózás nincs. A UI csak olvas (tábla).

**Közönség.** `contacts` (status: pending/subscribed/unsubscribed/cleaned, `attributes` jsonb, nincs
mező-definíció tábla), listák, tagek, szegmensek (`SegmentEngine`), űrlapok, consent
(`consents`, `consent_events`, `ConsentRecorder::imported()` soha nem ad `confirmed`-et). Kontakt-import
NINCS (CSV csak a Validation modulban, formula-injekció védelemmel). Kontakt CRUD UI nincs.

**Analitika.** `EventCounters`, `CampaignAnalytics`, `ListAnalytics`, `JourneyAnalytics`, `ClickMap`,
`AnalyticsExport` (csak CSV). Chart-könyvtár nincs, PDF nincs.

**Platform.** Domainek (DNS-rekord generátor, verify job, DKIM-rotáció) ✔; API-kulcsok (scope-ok,
last_used, visszavonás; IP-allowlist NINCS; **hiba**: a UI `validate` scope-ot ad, a route
`validate:run`-t vár); SMTP-hitelesítők ✔ (rotáció UI nincs); webhookok (10 eseménytípus, HMAC, replay,
`/v1`-en rotate-secret; UI-n nincs rotáció, teszt-esemény sehol); napló (szűrők, trace, statisztika;
export nincs); suppression (okok, a panasz/leiratkozás tenant által nem törölhető; törlésnél nincs
indoklás); IP-poolok read-only; OpenAPI `docs/openapi/ventmail-v1.yaml` (appban nem jelenik meg).

**i18n.** hu, en, de, it, es, ru (FR HIÁNYZIK). Szerver: `lang/*`, kliens: `resources/js/locales/*.json`
(teljesség-teszt). `users.locale` alapértéke `'hu'` → az `Accept-Language` és a ventSSO `locale`
claim sosem érvényesül. Felhasználói időzóna / beállítás tábla nincs.

**Tárolás / ventVault.** Feltöltés nincs; a ventVault `/v1` API-ja még nem él.
**ventPay.** `VentPayClient` interfész + `FakeVentPayClient`; `entitlement:<feature>` middleware.

**E2E.** 8 spec (app-shell, login, domain-wizard, logs, platform-screens, members-forms, studio,
platform-console), CI-ban fut.
